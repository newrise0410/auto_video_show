# 스파이크 — 로컬 TTS 모델 선정

한국어 내레이션에 쓸 로컬 TTS를 고르기 위한 베이크오프 기록. **2026-08-17** 기준.
하드웨어: RTX 3060 12GB / Ryzen 9 7950X3D / RAM 31GB.

## 결론

**Supertonic 3 를 채택한다.** 한국어 정확도, 속도, 설치 난이도 셋 다 Chatterbox보다 낫다.

다만 **요구했던 "음성 클로닝"은 이 조합으로는 얻지 못했다.** 아래 "미해결" 참조.

| | Supertonic 3 | Chatterbox Multilingual |
|---|---|---|
| 한국어 정확도 | 좋음 (숫자만 정규화 필요) | **사용 불가** |
| 영어 고유명사 | 정확 | 뭉갬 |
| 속도 | RTF 0.18 (**CPU**) | RTF 0.72 (CUDA) |
| 모델 로딩 | 0.9초 | 약 25초 |
| 크기 | 99M (ONNX) | 0.5B (torch) |
| 설치 | onnxruntime만 | torch CUDA 2.4GB |
| 라이선스 | 코드 MIT / 가중치 OpenRAIL-M | MIT (PerTh 워터마크 자동) |
| 오디오 클로닝 | **불가** (상용 Voice Builder 필요) | 가능 |
| 프리셋 보이스 | 10종 (M1~M5, F1~F5) | 없음 (레퍼런스가 기본) |

## 판정 방법

발음 품질은 귀로 들어야 하지만, **"숫자와 영어를 제대로 읽었는가"는 ASR 왕복으로
객관적으로 볼 수 있다.** 합성 결과를 로컬 faster-whisper(`small`, `language="ko"`)로
다시 받아 적어 원문과 비교했다. 전사가 무너지면 읽기를 틀린 것이다.

> faster-whisper는 Hermes venv에 이미 설치돼 있어 그대로 썼다. 전 과정이 로컬이라
> 외부로 오디오가 나가지 않는다. 언어를 강제하지 않으면 한국어를 영어로 오인해
> 번역해버리므로 `language="ko"` 가 필수다.

## 원문 대 전사

### Supertonic (정규화 없음) — `docs/tts-bakeoff/supertonic/`

| # | 원문 | 전사 | 판정 |
|---|---|---|---|
| 1 | 이 API를 쓰면 핸드드립보다 세 배 빠릅니다 | 이 **APL**을 쓰면 핸드드립보다 3배 빠릅니다 | 대체로 통과 |
| 2 | 원두 대 물 비율은 **1 대 15가** 기본값입니다 | 원두대 물 비율은 **1대18소가** 기본값입니다 | **실패** |
| 3 | **GitHub Actions**에서 **CI**를 돌리듯이 | **Github Actions**에서 **CI**를 돌리듯이 | 통과 |
| 4 | 30초에서 1분 정도 식히면 90도 초반까지 | 30초에서 1분 정도 시키면 90도 초반까지 | 통과 |
| 5 | 원두를 바꿔도 커피가 쓰다면 원인은 대개 추출에 | (원문 그대로) | 통과 |

영어 고유명사는 정확했고, **숫자에 조사가 붙는 형태에서만 무너졌다.**

### Supertonic + 텍스트 정규화 — `docs/tts-bakeoff-normalized/supertonic/`

「1 대 15가」를 「일 대 십오가」로 바꿔 넣자:

| # | 전사 | 판정 |
|---|---|---|
| 2 | 물 온도는 **92도**, 원두대 물 비율은 **1대15가** 기본값입니다 | **해결** |
| 4 | 30초에서 1분 정도 식히면 90도 초반까지 떨어집니다 | 완벽 |

`avs/tts/normalize_text.py` 가 존재하는 이유가 이 한 줄이다.

### Chatterbox — `docs/tts-bakeoff/chatterbox/`

| # | 전사 | 판정 |
|---|---|---|
| 1 | 이 **앞이**를 쓰면 핸드드립보다 **새벽** 빠릅니다 | 실패 |
| 2 | 물 온도는 **지가 지가 지고도** … **앳대근박세가** 기본값입니다 | 실패 |
| 3 | **킥탑 액션세서 씨**를 돌리듯이 | 실패 |
| 4 | **산초**에서 1분 정도 시키면 **잇지문도** 초반까지 | 실패 |
| 5 | 원두를 바꿔도 커피가 쓰다면 원인은 대개처출에 | 통과 |

**한국어 레퍼런스 오디오를 줘도 나아지지 않았다** (`docs/tts-bakeoff-koref/`).
Supertonic이 만든 한국어 음원을 레퍼런스로 물려 재측정했지만 2·3·4번은 그대로 무너졌다.
평문(5번)만 읽어내는 수준이라 내레이션에 쓸 수 없다.

## 합격 기준 대조

| 기준 | Supertonic | Chatterbox |
|---|---|---|
| 1. 영어를 자연스럽게 | 통과 | 실패 |
| 2. 숫자를 한국어 어법대로 | 정규화 후 통과 | 실패 |
| 3. 8초 합성 10초 이내 | 통과 (약 1.5초) | 통과 (약 5.8초) |
| 4. 수익화 허용 라이선스 | OpenRAIL-M (조건부 허용) | MIT |

## 알아둘 것

**합성이 비결정적이다.** 같은 문장을 두 번 합성하면 파형이 다르다(해시 불일치).
다만 **길이는 바이트 단위로 동일**해서 2-pass 타이밍은 안정적이다. 매니페스트에
길이를 기록해 두면 재실행해도 타임라인이 흔들리지 않는다.

**한국어 청크 상한이 120자다** (다른 언어는 300자). 그보다 길면 자동으로 쪼개고
사이에 `silence_duration` 만큼 정적을 넣는다. 씬당 내레이션은 32~40자라 걸리지 않는다.

**`lang="na"`가 멀티링구얼 모드다.** 한국어 문장에 영어가 섞여 있어도 언어를 지정하지
않고 통째로 넘길 수 있다. 코드스위칭 요구사항이 이걸로 해결된다.

**OpenRAIL-M은 사용 목적 제한이 있는 라이선스다.** 상업적 사용 자체는 막지 않지만
금지 용도 목록이 붙는다. 유튜브 콘텐츠 제작은 해당하지 않지만, 배포 형태를 바꿀 때
원문을 확인할 것.

## 미해결 — 음성 클로닝

요구사항은 "프리셋과 클로닝 둘 다"였는데, **테스트한 조합으로는 둘을 동시에 얻을 수 없다.**

- Supertonic: 한국어는 좋지만 오디오에서 바로 클로닝하지 못한다. 커스텀 보이스는
  상용 서비스(Voice Builder)가 만들어 준 스타일 JSON이 있어야 한다.
- Chatterbox: 클로닝은 되지만 한국어를 못 읽는다.

어댑터 인터페이스에는 `reference_audio` 를 그대로 남겨뒀다. Supertonic 어댑터는 이
값을 스타일 JSON 경로로 해석하므로, Voice Builder 결과물이 생기면 코드 수정 없이
연결된다. 오디오 클로닝이 꼭 필요하면 다음 후보를 더 봐야 한다:

- **CosyVoice2-0.5B** (Apache-2.0) — git clone 필요, 의존성 무거움
- **F5-TTS** (MIT) — 한국어 커뮤니티 체크포인트를 따로 구해야 함

## 재현

```powershell
uv run avs tts-bakeoff --models supertonic,chatterbox
uv run avs tts-bakeoff --models supertonic --out docs/tts-bakeoff-normalized --normalize
```

ASR 대조는 Hermes venv의 faster-whisper로 `language="ko"` 를 강제해서 돌린다.
