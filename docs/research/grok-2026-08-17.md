# Grok 리서치 원문 — 2026-08-17

`docs/roadmap.md` 의 근거 절반이 여기서 나왔다. 나중에 "이건 어디서 나온 얘기냐"에
답할 수 있도록 응답을 **손대지 않고** 그대로 남긴다.

- 모델: `grok-4.6` (xAI OAuth, 슈퍼그록 구독)
- 툴셋: `web`, `x_search`
- 소요: 약 15분

## 재현 방법

```bash
# Git Bash에서 (PowerShell 아님 — 아래 주의 참조)
cd "$LOCALAPPDATA/hermes/hermes-agent"
P=$(cat prompt.txt)
./venv/Scripts/hermes.exe -z "$P" --provider xai-oauth -m grok-4.6 -t web,x_search --ignore-rules
```

두 번 실패한 뒤에 성공했다. 걸린 지점:

1. **`--provider xai` 는 실패한다** — `No usable credentials found for provider 'xai'`.
   풀에 등록된 이름은 **`xai-oauth`** 다. `hermes auth list` 로 확인할 수 있다.
2. **PowerShell로 여러 줄 프롬프트를 넘기면 인자가 쪼개진다** — 줄바꿈 지점에서 잘려
   나머지가 하위 명령으로 해석되고 `invalid choice` 에러가 난다. Bash로 넘기거나
   파일에서 읽어야 한다.
3. `-z` 는 전부 끝난 뒤에 한 번에 출력한다. 진행 중에는 stdout이 비어 있어서
   죽은 것처럼 보이지만 정상이다.

## 보낸 프롬프트

현재 파이프라인 구조(6단계, 각 단계의 도구와 제약)를 먼저 설명하고, 다음을 요청했다:

- **A.** 비교 대상 OSS — 저장소 URL, 유지보수 상태, **훔칠 만한 구체적 아이디어**, 우리가 이미 나은 점
- **B.** 2025~2026 연구/기법 — 씬 간 일관성, 샷 플래닝, 강제 정렬(한국어), 자동 편집 문법, 쇼츠 리텐션의 **데이터 기반** 자료
- **C.** Grok Imagine 활용 심화 — image-to-video 워크플로, 프롬프트에서 실제로 차이를 만드는 요소, edit/extend 시나리오, 실패 모드
- **D.** X 실사용 관측

출력은 「즉시 적용 / 중기 / 실험적 / 하지 말 것」 4단계로, **각 항목에 URL 필수**,
**추측과 확인된 사실을 반드시 구분**하도록 지시했다.

마지막 지시가 결정적이었다. Grok은 내 웹 검색이 물어온 리텐션 수치들이 툴 마케팅
출처임을 스스로 지적하고 "1차 데이터 아님"으로 분류했다.

# 응답 전문

웹 페이지 본문 추출은 이 환경에서 막혀 검색 스니펫·공식 문서 URL·X 일부 원글만으로 썼습니다. 아래는 확인된 사실과 추측을 갈라 적습니다.

현재 파이프라인의 강점(OSS 대비): TTS 길이가 타임라인을 결정하는 2-pass, 한국어 숫자 정규화, 멱등 재개, 사이드체인 더킹+loudnorm, 목소리 구간에만 ASS, Grok 9:16 네이티브. 약점: 씬=클립 1:1, 인물/스타일 비일관, 훅 구조 없음, 단어 자막 없음, BGM 없음, 업로드·성과 루프 없음.

1. 즉시 적용 가능 (1~2일, 효과 큼)

(1) 기획 JSON에 "첫 3초 훅 샷"을 강제 필드화
왜: YouTube 1차 자료는 Shorts 피드가 클릭이 아니라 재생 후 시청 vs 스와이프로 갈린다고 명시합니다. https://blog.youtube/creator-and-artist-stories/renes-top-five-march-4-2024/  제품 리드 인터뷰도 스와이프 소비를 전제로 합니다. https://blog.youtube/creator-and-artist-stories/youtube-shorts-deep-dive/
할 일: 씬0을 `hook_visual` + `hook_line`(3초 이내 결론/충돌/숫자)로 분리. 지금처럼 풍경 와이드로 시작하면 스와이프에 짐.
주의: "인트로 유지율 70%" 같은 수치는 OpusClip 등 마케팅 블로그입니다. https://www.opus.pro/blog/ideal-youtube-shorts-length-format-retention  1차 데이터가 아님. 벤치마크가 아니라 가설로만 쓰세요.

(2) 텍스트→비디오를 버리고, 키프레임 이미지 → image-to-video
왜: 공식 I2V는 정지 프레임을 출발점으로 고정합니다. https://docs.x.ai/developers/model-capabilities/video/image-to-video  1.5는 I2V 네이티브 1080p. 레퍼런스-투-비디오는 `reference_image_urls`로 인물/의상/장소를 잠급니다. https://docs.x.ai/developers/model-capabilities/video/reference-to-video
할 일: 씬마다 (a) 캐릭터/구도 스틸 1장 생성 → (b) 그 URL을 I2V 입력 → (c) 직전 클립 마지막 프레임을 다음 씬 입력. 프롬프트는 동작·카메라만.
확인됨: `aspect_ratio`를 넣으면 입력 이미지를 늘릴 수 있음(문서). 9:16 스틸을 먼저 만들고 ratio는 생략하거나 입력과 같게.
추측: 마지막 프레임 체인이 씬 간 연속성을 가장 싸게 올립니다. X에서도 I2V+레퍼런스가 정석으로 반복됩니다. https://x.com/iamcurtismith/status/2087016574750273785

(3) 이미 있는 대본으로 한국어 단어 정렬 → 키워드 하이라이트 ASS
왜: 여러분은 TTS라 정답이 있습니다. ASR이 아니라 forced alignment가 맞습니다.
확인됨: Qwen3-ForcedAligner-0.6B는 한/영 포함 단어·글자 타임스탬프. https://huggingface.co/Qwen/Qwen3-ASR-1.7B  https://qwen.ai/blog?id=qwen3asr  https://arxiv.org/html/2601.21337v1
할 일: 씬 wav + 정규화된 한국어 대본 → 글자/어절 타임코드 → 현재 단어만 색 바꾸기. VideoLingo가 훔칠 구조는 "시간으로 자르지 말고 의미 단위로 줄바꿈". https://github.com/Huanshere/VideoLingo (~18k, 2026-07 푸시)
WhisperX는 영어 phoneme align이 본령. 한국어는 wav2vec2 정렬 모델이 따로 필요합니다. https://github.com/m-bain/whisperX  한국어 정렬 품질 벤치 직접 비교는 못 찾음. MFA 3.0은 정확하지만 사전·음향모델 세팅 비용이 큼. https://arxiv.org/html/2606.18466

(4) BGM 베드만 깔고, 이미 있는 사이드체인 더킹을 재사용
왜: MoneyPrinterTurbo(약 104k, 2026년에도 TTS 커밋 활성)가 오래전에 한 일: BGM+자막+합성. https://github.com/harry0703/MoneyPrinterTurbo  여러분은 더킹·LUFS가 이미 있어 하루 작업입니다.
할 일: 로열티 프리 1곡을 -20 LUFS 근처로 깔고 내레이션에 더킹. Grok 클립 환경음은 끄거나 -12dB로 내려 음악과 안 싸우게.
확인됨: 클립에 환경음이 이미 들어옴(사용자 시스템). 안 내리면 음량 전쟁이 납니다.

(5) ffmpeg zoompan으로 클립 내부 2~4% Ken Burns
왜: 컷을 늘리지 않고도 "죽은 화면"을 줄입니다. 씬=클립 1:1을 유지한 채 가능.
할 일: 내레이션 길이만큼 `zoompan=z='min(zoom+0.0008,1.08)'` 또는 약한 푸시인. 첫 3초는 줌 속도를 조금 더.
추측: 리텐션 효과 크기는 미검증. 구현 비용 대비 리스크는 낮음.
공식 "자막 스타일 A/B가 유지율을 X% 올린다" 논문/1차 데이터는 못 찾음.

2. 중기 (1~2주)

(1) 캐릭터/스타일 바이블 + reference_image_urls (최대 구성 확인 후 고정)
확인됨: 레퍼런스 이미지는 공식 기능. https://docs.x.ai/developers/model-capabilities/video/reference-to-video  X 쪽 설명은 최대 7장, 캐릭터/장소/소품 명명. https://x.com/grok/status/2088876663786364974
할 일: 에피소드당 턴어라운드 2~4장(정면/측면/전신/의상)을 이미지 모델로 고정 → 모든 I2V에 동일 URL. 프롬프트에 이름과 "same jacket zipper, same scar"급 불변 디테일.
실전 가이드(제품 블로그, 논문 아님): 캐릭터당 2~6장. https://invideo.io/faq/what-should-a-character-sheet-include-for-ai-video/  프로덕션 관점 레퍼런스 컨디셔닝. https://www.forasoft.com/learn/ai-for-video-engineering/articles-ai/character-scene-camera-consistency-production
우리가 이미 나은 점: 로컬 TTS+정규화+재개. 저네(MoneyPrinter/ShortGPT)는 보통 Pexels 스톡이라 인물 일관성 문제 자체가 없음 = 회피.

(2) 샷 플래닝을 MovieAgent식으로 계층화
확인됨: MovieAgent는 director → scene plan → shot plan 다에이전트 CoT. https://arxiv.org/abs/2503.07314  https://weijiawu.github.io/MovieAgent/  ViMax도 스토리보드 LLM-judge 템플릿. https://arxiv.org/html/2606.07649v1
훔칠 구조(막연한 "더 좋은 프롬프트" 아님):
- 씬 JSON에 `shot_size`(ECU/CU/MS/WS), `camera`(static/push/pan/orbit), `action`, `must_keep`(의상/소품), `forbidden`(새 인물)
- 인접 샷은 사이즈를 바꾸기 (MS→CU). 같은 WS 5연속이 지금 퀄이 무너지는 이유.
ShortGPT가 가진 구조적 아이디어는 LLM용 Editing Markup Language. 유지보수는 정체. https://github.com/RayVentura/ShortGPT (~5.9k, https://ghtrends.dev/RayVentura/ShortGPT/ ) 엔진을 베끼지 말고 샷 스키마만.

(3) 씬 1개 = 클립 1개를 깨기: 내레이션은 1트랙, 비주얼은 2~3컷
왜: 18.5초/5씬은 컷 문법이 없습니다. NarratoAI(~8.8k)는 반대로 기존 영상을 LLM이 잘라 내레이션에 맞춥니다. https://github.com/linyqh/NarratoAI  여러분은 생성 영상이라 반대 방향: 긴 I2V 1개를 단어 강세에서 자르거나, 같은 레퍼런스로 앵글만 다른 짧은 클립 2개를 붙이기.
도구: auto-editor는 무음 기준 컷이라 나레이션 쇼츠엔 거의 쓸모 없음(침묵이 없음). https://github.com/WyattBlue/auto-editor  쓰지 마세요.
할 일: 대본의 강세 단어 시점에 hard cut. ffmpeg concat은 이미 있음.

(4) 업로드 자동화 + 메타데이터 JSON
MoneyPrinterV2(~31k, 최근 Post Bridge 커밋 흔적)가 가진 유일한 구조적  steals: 생성과 배포를 같은 앱에 붙임. https://github.com/FujiwaraChoki/MoneyPrinterV2  https://gittrend.io/repo/FujiwaraChoki/MoneyPrinterV2
할 일: YouTube Data API로 Shorts 업로드, 제목/설명/해시태그를 기획 JSON에서 생성. 수동 업로드가 피드백 루프를 죽입니다.
확인됨: V2는 AGPL. 코드 흡수 시 라이선스 주의.

(5) extend로 "같은 샷을 더 길게", edit는 모델 분기
확인됨:
- Extension: 마지막 프레임에서 이어 붙임, 입력 2~15초, 연장 2~10초. https://docs.x.ai/developers/model-capabilities/video/extension
- Edit: `grok-imagine-video` 전용. **1.5는 미지원**. 입력 영상 상한 약 8.7초, aspect 커스텀 불가. https://docs.x.ai/developers/model-capabilities/imagine  https://docs.x.ai/developers/model-capabilities/video/editing
파이프라인 시나리오: TTS가 12초인데 I2V가 8초면 extend. 손만 이상하면 1.0 edit. 새 씬은 extend하지 말고 새 I2V(마지막 프레임 입력).
가격 확인됨(프리뷰): 1.5 출력 약 $0.08/초 + 이미지/비디오 입력 과금. https://docs.x.ai/developers/models/grok-imagine-video-1.5-preview
추측: 매 씬 15초 풀젠보다 "짧은 클린 테이크 + extend"가 실패율·비용 모두 나을 수 있음. 직접 A/B 필요.

Grok 프롬프트에서 실제로 갈리는 것 (문서 예시+실무, 논문 아님)
차이 큼(확인에 가까움): 카메라 동사 1개(slow push-in / locked-off / orbit), 시간(5s of subtle breathing vs chaotic), 시작 프레임과의 관계("animate this exact frame"), 네거티브(morphing face, extra limbs). 공식 예시가 이미 카메라 언어를 씁니다. https://docs.x.ai/developers/model-capabilities/video/reference-to-video
차이 작음/역효과(추측): 형용사 나열, "cinematic masterpiece", 렌즈 mm를 환각으로 넣기, 한 프롬프트에 샷 3개.
실패 모드(확인+관측): 레퍼런스 없이 T2V 하면 얼굴 표류 https://x.com/SomeDudeTex/status/2086918342653121004 ; aspect 강제 스트레치; 1.5에 edit 호출; 클립 베이크된 오디오 때문에 더킹 꼬임; 복잡한 다시점·다중 인물.

3. 실험적 / 불확실

(1) 성과 피드백 루프 (조회·3초 유지·완주율을 다음 훅 프롬프트에)
불확실한 이유: YouTube Analytics API로 숫자는 가져올 수 있으나, 어떤 훅 타입이  elevates하는지는 채널·주제 종속. "데이터 기반 자막 스타일" 1차 연구는 못 찾음. 마케팅 글만 많음. https://aibrify.com/blog/youtube-shorts-retention-curve-playbook
하면: 업로드 응답의 videoId를 기획 JSON에 기록 → 48h 후 유지율 곡선만 저장. 프롬프트 자동 최적화는 표본 50개 전엔 하지 말 것.

(2) Remotion / html-video로 캡션 엔진 교체
불확실한 이유: 지금 ASS+ffmpeg가 이미 loudnorm/더킹과 한 몸. React 렌더러는 Windows 로컬에서 설치·캐시 무효·폰트 이슈가 큼. 이득은 캡션 애니메이션뿐.
조건: 단어 하이라이트가 ASS로 한계일 때만 html-video 템플릿을 자막 레이어에만.

(3) 로컬 ConsisID / VACE로 일관성 이전
ConsisID CVPR 2025, 튜닝 없이 신원 유지 T2V. https://arxiv.org/abs/ 검색 히트: https://pku-yuangroup.github.io/ConsisID/  https://github.com/PKU-YuanGroup/ConsisID
VACE ICCV 2025, R2V/V2V 통합. https://arxiv.org/abs/2503.07598  https://github.com/ali-vilab/VACE

# 검토 메모 (원문 아님)

응답을 받은 뒤 내가 직접 확인한 것:

| Grok 주장 | 검증 결과 |
|---|---|
| 1.5의 I2V가 네이티브 1080p | **확인됨.** 공식 문서에 그대로 있음 |
| Qwen3-ForcedAligner-0.6B가 한국어 지원 | **확인됨.** 11개 언어, 5분까지, WhisperX보다 정렬 오차 낮다고 보고 |
| `reference_image_urls` 최대 7장 | **부분 확인.** 문서는 최대치를 명시하지 않고 예시에 3장. Hermes 플러그인 코드에는 `MAX_REFERENCE_IMAGES = 7` |
| reference-to-video는 720p 상한 | **미확인.** 문서는 예시로 720p를 보일 뿐 상한을 명시하지 않음 |
| 1.5는 edit 미지원 | **미확인.** 재확인하지 못함 |
| extension 입력 2~15초 / 연장 2~10초 | **부분 확인.** 문서는 `duration` 이 연장분만 의미한다고만 명시. 수치 범위는 확인 못 함 |
| Qwen 정렬기 링크 | URL 하나가 `Qwen3-ASR-1.7B` 를 가리킴. 정확한 주소는 https://huggingface.co/Qwen/Qwen3-ForcedAligner-0.6B |
| MoneyPrinterV2가 AGPL | **확인됨.** GitHub API에서 `AGPL-3.0` |
| ShortGPT 유지보수 정체 | **확인됨.** 최종 푸시 2025-02-10 (18개월) |
| 스타 수 어림치 | **여러 곳이 틀림.** ViMax 7k→실제 11,994 / ShortGPT 5.9k→7,824 / NarratoAI 8.8k→10,737 / Remotion 10k+→56,529 |

문서 본문 추출이 막힌 환경에서 스니펫만으로 쓴 것치고 정확도가 높았다. 특히 **내 웹 검색이
물어온 리텐션 수치들을 툴 마케팅 출처로 정확히 분류**한 점이 유용했다.
