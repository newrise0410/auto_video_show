# 스파이크 — 대본 전달력

**2026-08-20** 기준. 오디세우스 롱폼(36씬 / 6분 24초)을 뽑아 보니 한국어가 어색했다.
"낱말의 뜻이 이상하고, 문장력이 떨어지고, 흐름이 이어지지 않는다"는 지적에서 출발했다.

## 이 문서의 규칙

`docs/roadmap.md` 와 같은 표기를 쓴다.

- **[확인됨]** — 1차 출처 또는 직접 실측으로 확인
- **[미확인]** — 그럴듯하지만 1차 출처를 못 찾음
- **[추측]** — 근거 없는 판단. 실행 전에 직접 재봐야 함

## 결론

**결함은 s2(대본)가 아니라 s1(구성안)과, s2에게 준 지시문에서 나왔다.** [확인됨 — 직접 대조]

어색한 표현 여섯 개가 전부 구성안에 그대로 있었다.

| 대본 (s2) | 구성안 (s1) |
|---|---|
| 저주가 **성립했습니다** | 저주가 **성립했다** |
| 대가는 곧바로 **청구되지** 않았습니다 | 대가는 즉시 **청구되지** 않았다 |
| 귀향길의 첫 **기항지** | 귀향길 첫 **기항지**에서 |
| 그의 **전술**이었습니다 | 그의 **전술**이었다 |
| 정면 승부는 **선택지**가 아니었습니다 | 정면 승부는 애초에 **선택지**가 아니었다 |
| 약속을 시간으로 **무력화**했습니다 | 약속을 시간 자체로 **무력화**했다 |

s2는 글을 쓰는 게 아니라 `-다` 를 `-습니다` 로 바꾸는 변환기로 돌고 있었다. 그렇게
만든 건 `avs/prompts.py` 에 있던 이 문장이다.

> **이 구성안이 영상의 내용을 확정합니다.** 대본 작가는 여기 적힌 항목을 순서대로
> **문장으로 옮길 뿐**, 무엇을 다룰지 다시 고르지 않습니다.

내용 유실을 막으려고 넣은 문장인데, 대본 작가에게서 **문장을 쓸 권한**까지 뺏었다.
이 한 문장이 세 축을 한꺼번에 설명한다 — 낱말은 구성안의 낱말이고, 어미는 기계적
변환의 산물이며, 구성안이 관계 표시 없는 평평한 목록이라 흐름이 생길 자리가 없다.

## 실측 — 무엇이 문제였고 무엇이 아니었나

36씬 / 87문장 / 2691자. `avs lint` 로 측정. [확인됨 — 직접 실측]

| 지표 | 실측 | 판단 |
|---|---|---|
| 합쇼체(`-습니다`) 비율 | **92%** | 문제 |
| **같은 어미 연속 최장** | **40문장** | **가장 강한 증거** |
| 인접 문장 동일 어미 | 85% | 문제 |
| 접속으로 여는 씬 | 5/35 = 14% | 문제 |
| 낱말 사전 히트 | 7건 | 문제 |
| 문장 길이 최소/중앙/최대 | 8 / 30 / 57 | **정상 — 이미 다양하다** |
| 문두 주어 반복 | 18% | 임계 미만 |
| 아라비아 숫자 | **0개** | 모델이 이미 「열두 명」으로 쓴다 |
| 전형적 번역투 | 피동 1 / `~에 대한` 0 / `~것입니다` 0 | **없다** |
| `의` 사용 | 문장당 0.26 | 남용 아님 |
| `명사+하다/되다` | 11건 | **탐지기로 못 쓴다** |

### 죽은 가설 세 개

**1. 글자수 예산이 원인이다 — 틀렸다.** 쇼츠(32자)에서 어미가 잘린 건 사실이지만,
롱폼 96자에는 해당되지 않는다. LIFEBench는 길이 제약이 출력 품질을 일반적으로
해치지 않는다고 보고한다. https://arxiv.org/pdf/2505.16234 [확인됨 — 논문]

**2. 문장 길이 리듬이 깨졌다 — 틀렸다.** 8/30/57자로 이미 다양하다. 검사를 걸어봐야
아무것도 안 걸리거나 정상을 잡는다.

**3. `명사+하다/되다` 로 추상 한자어를 잡을 수 있다 — 틀렸다.** 11건 중 실제 문제는
성립·청구·무력화 셋뿐이고, 기도했고·제안했습니다·지시했습니다·착각하는은 전부
자연스럽다. **패턴으로 잡으면 멀쩡한 문장을 잡는다.**

### 그래서 결함의 정체는

**문법적 압축이 아니라 낱말 층위의 분야 불일치다.** 계약·회계·군사·게임·해운의 말이
신화 낭독에 섞였을 뿐, 한자어에 문법은 이미 붙어 있다. `의` 가 0.26/문장으로 낮고
명사 쌓기도 거의 없다. 따라서 **선별된 낱말 목록만이 실제 사례를 가리킨다.**

## 계측 — `avs lint`

`docs/spike-local-tts.md` 가 "발음이 좋은가"를 ASR 왕복이라는 객관 대리 지표로 바꾼
것과 같은 방식이다. 주관적 질문에서 잴 수 있는 조각만 떼어낸다.

```powershell
uv run avs lint <run_id>
uv run avs lint --file runs/<id>/02_script.json --before runs/<id>/02_script.v1.json
```

**여기 수치는 한 방향 증거다.** 나쁘면 확실히 나쁘고, 좋다고 좋은 대본이라는 뜻은
아니다. 「저주가 걸렸습니다」가 「저주가 성립했습니다」보다 나은 이유는 사전 히트가
줄어서가 아니다. **최종 판정은 소리 내어 읽어보는 것이다.**

임계값은 게이트가 아니라 경고다. 지표를 규범으로 굳히면 프롬프트가 지표를 속이는
쪽으로 진화한다.

### 왜 비율이 아니라 연속인가

비율은 뒤쪽에 변화를 몰아넣어도 충족되지만 귀가 듣는 건 연속이다. 실측에서 비율
92%보다 **연속 40문장**이 훨씬 정확한 증상 기술이었다.

합쇼체 판별은 끝 3자가 아니라 **`니다` 앞 음절의 받침이 ㅂ인지**로 한다. 끝 3자로
세면 했습니다/었습니다/갔습니다가 서로 다른 어미로 잡히는데 귀에는 같은 소리다.
또 「아무도 아니다.」 같은 인용된 해라체를 오검출하면 안 된다. [확인됨 — 테스트]

## 고친 것

전부 `avs/prompts.py` + `avs/stages/s2_script.py` 안에서 끝났다. 새 스테이지 없음.

1. **공유 낱말 기준** (`KOREAN_DICTION`) — s1·s2 양쪽 시스템 프롬프트에 들어간다.
   s1에 닿는 게 핵심이다. 기준은 한자어냐 고유어냐가 **아니라** "소리 내어 읽었을 때
   한 번에 알아들리는가" 하나뿐이다.
2. **s2에게 문장 권한 반환** — "문장으로 옮길 뿐"을 걷어내고 내용과 문장을 분리했다.
3. **`## 전개` 에 But/Therefore 태그** — `- [핵심][그래서] …` / `[하지만]` / `[전환]`.
   **`[그리고]` 는 없다.** 둘 중 어느 쪽으로도 안 이어지면 나열이므로 지우거나 합치거나
   순서를 바꾼다. 이러면 한국어 접속사가 문체 지시가 아니라 **구조에서 생성된다.**
4. **어미 회전 + 주어 생략 규칙**.
5. **깨진 재시도 수리** — 백엔드에 대화 기록이 없어서(`complete()` 는 매번 새
   서브프로세스) 재시도 때 모델이 구성안도 자기 직전 출력도 못 보고 있었다. "씬 14의
   어미를 바꾸세요"가 실행 불가능한 지시였던 것이다. 이제 첫 메시지 전문 + 직전 출력을
   함께 보낸다.
6. **문체 검사 3종 + 소프트 실패 계약** — `script is None` 이면 못 씀,
   script 가 있는데 problems 가 있으면 고치면 좋음. 문체 때문에 36씬 실행이 죽지 않는다.

### 근거로 삼은 작법

- **But/Therefore 원칙** — 비트 사이를 잇는 말이 "그리고 나서"면 이야기가 아니다.
  https://perell.com/note/but-therefore-rule/ [확인됨 — 1차 출처]
- **주어 생략** — 국립국어원이 인칭대명사 남용을 번역투 1순위로 꼽는다.
  https://www.korean.go.kr/nkview/nklife/1990_2/21_4.html [확인됨]
- **번역투 단속의 한계** — 문제는 외래 표현이라서가 아니라 명료함을 해쳐서다.
  https://www.ppss.kr/news/articleView.html?idxno=79671 [확인됨]
- **낭독 검사** — 한국 방송작가 실무("소리 내어 읽어보면 얼마나 문어체적인지 알 수
  있다")와 영어권 AI 교정 실무("read it out loud")가 독립적으로 같은 결론에 닿았다.
  https://brunch.co.kr/@kimleehyo/16 · https://www.louisbouchard.ai/ai-editing/ [확인됨]
- **낱말 사전 출처** — 국립국어원 다듬은 말 / 쉬운 우리말 사전.
  https://www.korean.go.kr/front/imprv/refineList.do?mn_id=158 ·
  https://www.plainkorean.kr/ko/dictionary/dic_new.do

## 하지 않은 것

| 하지 않음 | 이유 |
|---|---|
| **윤문(polish) 스테이지 신설** | 원인이 s1인데 윤문 단계부터 만들면 s2에 시킨 손상을 LLM 호출로 되돌리는 꼴이다. 재시도 수리가 그 패스를 무료로 준다. 계측 후 재판단 |
| `chars_per_second` 내리기 | 길이 제약은 원인이 아니다. 방송 6.2자/초는 **자막 읽기** 속도지 TTS 속도가 아니다 |
| 문장 길이·주어 반복 검사 | 실측상 정상. 정상을 잡거나 아무것도 못 잡는다 |
| 낱말 사전 자동 치환 | 「저주가 성립했다」는 고쳐야 하고 「계약이 성립했다」는 옳다. **사전은 탐지기다** |
| `Scene` 에 `connector` 필드 | 아무도 안 읽는 메타데이터가 되고, 모델이 내레이션 본문 대신 JSON 필드로 태그를 충족시키려 든다. TTS가 읽는 건 본문이다 |
| `normalize()` 에 한글 숫자 지원 | 아라비아 숫자 0개. 모델이 이미 올바르게 쓴다 |
| LLM에게 대본 10점 채점 | 재현 불가. 로드맵 G절 "마케팅 수치를 KPI로 박제"와 같은 실수 |

용어 주의: **`2-pass`** 는 narrate-before-clips 를 뜻하고 **`검수/Verifier`** 는 로드맵
E절 VLM 판정자가 선점했다. 대본 쪽에 이 말을 재사용하면 안 된다.

## 못 찾음 / 미확인

정직하게 남긴다. 여기 있는 항목을 근거로 결정하면 안 된다.

- **`FORMAL_RATIO_MAX = 0.70` 은 추측이다.** 한국어 내레이션 참조 코퍼스가 없다.
  재시도가 계속 3회에 닿으면 0.75로 풀되 **연속 검사는 건드리지 말 것** — 지각적
  작업을 하는 건 그쪽이다.
- **모델이 `~죠` 남발로 비율 검사를 속일 수 있다.** 습니다/죠 교대는 비율·연속을
  둘 다 통과하면서 지금보다 나쁘게 들린다. 관측되면 연속 검사를 3분류로 확장한다.
  미리 만들지는 않았다.
- **어미 회전이 TTS 발음을 해치는지 확인 안 됐다.** Supertonic이 `~더군요`·`~던
  겁니다` 를 `~습니다` 만큼 자연스럽게 읽는지 모른다. 기존 `avs tts-bakeoff` 로 ASR
  왕복 검사가 그대로 된다. [미확인]
- **시제 정책이 없다.** 씬 안에서 과거·현재가 섞이는 걸 lint가 보고만 하고 프롬프트는
  아무 말도 하지 않는다. 다큐 내레이션의 시제 정책을 규정한 한국어 출처를 못 찾았다.
- **고유명사 diff가 부정확하다.** 조사 앞 한글 2~6자를 후보로 잡아서 「있지」,
  「해쳤다」 같은 것이 섞인다. 전후 비교의 눈길 끌기 용도로만 쓸 것.
- **Supertonic 한국어 청크 상한 120자** — DeepWiki 자동 생성 문서와 서드파티
  글에서만 봤고 설치된 버전의 `pipeline.py` 를 직접 읽지 않았다. [미확인]
- **재시도 페이로드 크기** — 구성안 + 직전 JSON을 매번 다시 보낸다. `claude`/`codex`
  CLI의 실제 입력 한계는 측정 안 했다.
- **`[선택]` 항목이 잘릴 때 접속 태그가 어긋난다.** 태그 사슬은 구성안 순서 기준인데
  s2가 중간 항목을 버리면 살아남은 연결어가 틀릴 수 있다.
